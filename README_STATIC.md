# ФПиКЭИАС — статическая версия для GitHub Pages

Этот документ описывает, как запустить и опубликовать **статическую** версию проекта (HTML/CSS/JS) на GitHub Pages.

---

## Цель миграции

Исходный проект был серверным (Flask/Python).  
Для GitHub Pages требуется полностью статический сайт, поэтому логика расчётов перенесена в JavaScript.

---

## Структура статической части

Рекомендуемая структура:

```text
ФПиКЭИАС/
└── docs/
    ├── index.html
    └── assets/
        ├── style.css
        └── app.js
```

- `docs/index.html` — основной интерфейс всех модулей.
- `docs/assets/style.css` — стили.
- `docs/assets/app.js` — формулы и логика калькуляторов в браузере.

> GitHub Pages для репозитория обычно публикует содержимое папки `docs/`.

---

## Локальная проверка

Можно открыть `docs/index.html` напрямую в браузере, но лучше запустить простой локальный сервер:

### Вариант 1 (Python)
```bash
cd ФПиКЭИАС
python -m http.server 8080
```

После этого открыть:
- `http://localhost:8080/docs/`

### Вариант 2 (VS Code Live Server)
Открыть проект в VS Code и запустить `docs/index.html` через расширение Live Server.

## Публикация на GitHub Pages

1. Закоммитьте изменения в ветку (обычно `main`).
2. Перейдите в:
   - `Settings` → `Pages`
3. В разделе `Build and deployment`:
   - `Source`: **Deploy from a branch**
   - `Branch`: `main`
   - `Folder`: **/docs**
4. Сохраните настройки и дождитесь деплоя.

URL будет вида:

```text
https://<username>.github.io/<repo-name>/
```

---

## Важные правила для статической версии

1. **Никаких серверных маршрутов** (`/module1/...`, Flask endpoint и т.п.).
2. Все зависимости должны быть:
   - либо локальными (в `docs/assets`),
   - либо подключаться по CDN.
3. Используйте **относительные пути**:
   - `./assets/style.css`
   - `./assets/app.js`
4. Все вычисления — только на клиенте (JS).

## Рекомендации по качеству

- Добавить в `app.js` единые функции:
  - форматирования чисел и валют,
  - безопасного деления,
  - валидации входных данных.
- Для сложных модулей разбить код на:
  - `calculators/module1.js`, ..., `module8.js` (опционально),
  - либо оставить единый `app.js`, но с чёткими секциями.
- Добавить smoke-тесты расчётов (например, через Playwright/Vitest).

## FAQ

### Почему GitHub Pages не запускает Flask?
Потому что GitHub Pages хостит только статический контент (HTML/CSS/JS), без серверного Python runtime.

### Можно ли оставить часть логики на Python?
На GitHub Pages — нет.  
Если нужен Python backend, используйте отдельный хостинг для API (Render, Railway, VPS и т.д.), а фронтенд оставьте статическим.

### Можно ли публиковать не из `docs`, а из корня?
Да, но для текущей структуры рекомендуется `docs` как наиболее чистый и предсказуемый вариант.
